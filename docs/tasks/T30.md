# T30 — Horizon fit, service catalogue, and target architecture

**Status:** Complete — target design documented; none of the proposed web/billing components is claimed deployed

## Objective and scope

Decide which requirements Horizon can satisfy, define the custom billing/audit boundary, classify the supported service catalogue, and update delivery and architecture diagrams.

**Dependencies:** T29.
**Mapped requirements:** Expanded admin, tenant, security, usage/billing, acceptance, and staging goals.
**Record:** [Browser-ready goal and audit](../architecture/browser-ready-cloud-goal.md); [current delivery flow](../architecture/ProjectDeliveryflow.md).

## Decision

- Use Horizon as the browser surface for Keystone login and native OpenStack resource/admin panels when the underlying service and policy exist.
- Implement project billing, rate administration, immutable statements, and complete portal-action audit as custom backend capabilities with Horizon panels. Backend code must re-check verified Keystone identity, project scope, and role.
- Keep payment collection and tax-compliant invoices separate and unimplemented.
- Core first catalogue: Keystone, Nova, Glance, Neutron, project-scoped SSH or verified console access. Cinder volumes/snapshots and Swift object storage remain conditional on a supported backend/service. Ceilometer/Gnocchi is the first metering candidate; CloudKitty is optional rating software, not a statement/payment system.
- Preserve the supplied image as historical source. Its H100/MIG, Proxmox-first, third-party SSO, payment and other optional components are not evidence of local deployment.

Official feature references: [Horizon user guide](https://docs.openstack.org/horizon/2024.1/user/), [Horizon admin guide](https://docs.openstack.org/horizon/2024.1/admin/), [Horizon extension docs](https://docs.openstack.org/horizon/2024.1/contributor/), [Ceilometer 2024.1](https://docs.openstack.org/ceilometer/2024.1/), and [CloudKitty rating-service docs](https://docs.openstack.org/cloudkitty/latest/index.html).
