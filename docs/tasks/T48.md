## Implementation and evidence

`manage_cinder_loop.py` adds identity-based attachment of the existing Cinder
image, verifies its original PV UUID/VG before updating its dedicated LVM
filter, and never detaches another device or formats/creates an image/PV/VG.
The systemd helper reuses an existing matching attachment after a service
restart, or selects a free device after a reboot. Swift keeps its own mount.
The old installation preparer's historical defaults are retained; its scoped
inventory helpers and Cinder configuration verifier accept a validated device
from protected current state.

Live application passed: Cinder volume service active, existing image attached
to `/dev/loop3`, original PV UUID matched. Protected migration record:
`/root/openstack-poc-acceptance/cinder-loop-migration-dwea5tno/report.json`.
Nine new attachment safety tests and twelve existing Cinder tests passed.

`return_poc_to_service.py` checks the live required services and Cinder/Swift
APIs, then optionally starts only the preserved guest with an exclusive durable
intent. It does not run any backup/recovery rehearsal or replace resources.
Four offline tests verify ownership, settled state, no duplicate start, and
preservation of an ambiguous start intent.

Live return to service passed: all **27** required units active; retained VM
**ACTIVE**; existing pinned SSH identity, guest network/MTU ping, CPU smoke and
KVM verified. Cinder API, scheduler/volume heartbeat and backend free capacity

`/root/openstack-poc-acceptance/return-to-service-20261027.json`.
