## Historical state and blockers at initial audit

1. T15 is blocked: no usable Neutron network has been verified.
2. The actual Ubuntu 22.04 WSL host has no `openstack` CLI and no `nova-api`, `nova-compute`, or `neutron-server` systemd units. The checked conventional API ports had no listeners. These checks do not rule out containers or remote services, but none is approved or configured for this local POC.
3. `/dev/kvm` and `/dev/vhost-net` exist but are inaccessible to `sneha` because their numeric GID (993) does not match the local `kvm` group (109). Packaged udev rules specify `GROUP="kvm", MODE="0660"`, and `systemd-udevd` is active, yet the nodes remain gid 993. `/dev/vhost-net` has no observed sysfs device path; the exact node-ownership source and persistent fix remain unverified. See the [KVM device-group follow-up](../architecture/environment-audit.md#kvm-device-group-follow-up--2026-10-24).
4. At the time of the initial T16 audit, the deployment method/release choice was unresolved. The host recovery update below selects Ubuntu Cloud Archive Caracal packages as the Jammy POC candidate, but no deployment is approved or installed.
5. The current job tracker and asynchronous lifecycle service are fixture-specific. Real Nova integration must preserve provider identity and must never encode a Nova server ID as a fixture ID. The current implementation does not prove real Keystone authorization, Nova lifecycle, or Neutron behavior.
