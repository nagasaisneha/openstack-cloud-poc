## Objective and scope

Run the complete user-requested workflow through the browser and verify backend authorization, quota enforcement, resource results, usage calculations and statement visibility with two disposable test projects.

**Dependencies:** T32–T39.
**Mapped requirements:** Full acceptance demonstration and cross-tenant security requirements.

## Acceptance criteria

1. An administrator logs in, creates two projects with separate users, assigns least-privilege roles and independent quotas.
2. Each user logs in and sees only their account, project membership, roles, quotas, resources, usage and bills.
3. Each tenant creates and accesses a supported resource; provider status and provisioning errors are truthful.
4. Cross-project detail/list/usage/statement requests and unauthorized mutations are rejected by the backend, not only hidden in Horizon.
5. Quota overrun is denied by the provider and reflected clearly in the browser.
6. Real usage for the controlled workloads is collected, attributed and reconciled. Pricing creates reproducible itemized project statements.
7. Each tenant can download only its authorized project statement; the admin can compare both tenants' usage and charges.
8. Tests confirm project users share the project bill and user IDs do not create separate billable tenants.
9. Cleanup removes only explicitly task-owned test resources/identities and records independent provider absence. The retained demo VM and historical billing records remain.

**Evidence:** Sanitized browser screenshots/steps, request/response outcomes, provider IDs and states, quota results, meter source records, independent Decimal calculation, denial results, and cleanup report. Never capture credentials or tokens.
