## Scope and decisions

- **Original requirements:** POC-020 — repeatable infrastructure automation; staging release-plan Gates 0–2.
- **Dependencies:** T17 core lifecycle evidence; staging target, operator, network, hardware, storage and resource approvals.
- **Deployment candidate:** Kolla Ansible 23.0.0 / OpenStack 2026.2 Hibiscus / Ubuntu 24.04 LTS on a separate dedicated staging environment. The existing Ubuntu 22.04 WSL2 / Caracal POC is preserved and is not an upgrade target.
- **Host constraint:** The current WSL reports 7.7 GiB RAM total and is below Kolla's documented 8 GiB minimum; Docker Desktop integration is unavailable from the current shell. No local Kolla deployment is feasible or authorized based on this host check.

## Implementation

- Added `deployment/kolla/requirements.in` with exact Kolla Ansible and Ansible Core versions and `requirements.lock` with hashes for the full Python 3.12 dependency graph.
- Added an RFC 5737 multi-node inventory example and secret-free Kolla globals templates. Cinder, Swift, Ceilometer/Gnocchi, Prometheus/Grafana and Fluentd stay disabled by default; storage and monitoring profiles require separate review.
- Added `preflight.yml`, a read-only Ansible playbook requiring Ubuntu 24.04, 8 GiB RAM, two non-loopback interfaces, a dedicated storage mount with at least 40 GiB free, an approved change ID, architecture review, and backend/ring/metering/resource-budget decisions before optional services can be enabled.
- Added a deployment README defining Gate 0/1 inputs, protected credentials, version and image provenance, service bootstrap/deploy separation, smoke evidence and rollback expectations.
- Added `.github/workflows/ci.yml`: offline unit tests on Python 3.10 and 3.12 plus pinned deployment dependency installation, inventory parsing and Ansible playbook syntax validation on Ubuntu 24.04. CI is configured but has not yet run on GitHub.
- Added ignore rules for generated deployment secrets, local inventories, clouds.yaml and virtual environments.
