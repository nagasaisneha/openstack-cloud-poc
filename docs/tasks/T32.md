# T32 — Horizon deployment and secure browser login

**Status:** Blocked — Horizon is absent and this shell cannot inspect or safely reconfigure the shared systemd/Apache host

## Objective and scope

Deploy the release-compatible Horizon dashboard on the local POC without replacing the Ubuntu 22.04/Caracal installation or disrupting its shared Apache routes, authenticated APIs, or retained demo VM. Provide a verified browser URL and secure Keystone login for both administrator and tenant users.

**Dependencies:** T30.
**Mapped requirements:** Admin and tenant browser login, secure sessions, HTTPS, browser-ready delivery, startup/shutdown.
**Current blocker:** The repository audit records Horizon absent, no HTTPS listener on 443, and no noVNC listener on 6080. In this continuation the shell could not connect to the systemd bus or inspect the running Apache vhost state, so those historical observations have not been freshly verified. No package was installed. The current shared Apache routes and running cloud must be preserved. A protected Ubuntu operator context is required to capture fresh state and execute a reviewed install/rollback plan.

## Acceptance criteria

- [ ] A dedicated browser URL is verified from the intended Windows/WSL user context and is documented; it does not point to a raw API discovery document.
- [ ] TLS is enabled for the supported access path. Cookies are secure/HTTP-only, CSRF is enforced, session storage is suitable for the deployment, and secrets are injected from protected host configuration.
- [ ] Admin and tenant accounts authenticate through Keystone; no credentials are committed or duplicated in an application database.
- [ ] Existing Keystone, Placement, Glance, Nova, Neutron, Apache legacy routes, and retained VM health are checked before/after. Configuration backup, rollback and port ownership are recorded.
- [ ] Horizon panels are compared with scoped API results for the same users/projects.
- [ ] Operator runbook includes start, stop, health, TLS renewal, recovery and troubleshooting.

## Verification boundary

Package installation, Apache edits/reload, listeners, and live authentication change host state or contact protected services. First complete the read-only host review and present an exact change/rollback plan. The repository implementation goal does not authorize exposing a public listener.
