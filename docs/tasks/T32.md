# T32 — Horizon deployment and secure browser login

**Status:** Blocked — Horizon is absent, the shared Apache path is HTTP-only, and cloud authentication is unavailable

## Objective and scope

Deploy the release-compatible Horizon dashboard on the local POC without replacing the Ubuntu 22.04/Caracal installation or disrupting its shared Apache routes, authenticated APIs, or retained demo VM. Provide a verified browser URL and secure Keystone login for both administrator and tenant users.

**Dependencies:** T30.
**Mapped requirements:** Admin and tenant browser login, secure sessions, HTTPS, browser-ready delivery, startup/shutdown.
**Current blocker:** The operator's 2026-10-25 read-only checks confirm Horizon is not installed, Apache is active with a port 80 listener and no port 443 listener, and OpenStack CLI authentication currently fails. No package was installed. The existing Keystone and Placement vhosts and shared Apache service must be preserved.

## Package and access-path review

- `apt-get -s --no-install-recommends install openstack-dashboard` is only a package simulation: it proposes 18 new packages and an upgrade to `python3-yaml`; no changes were applied.
- The Ubuntu Cloud Archive Horizon 24.0.1 package was downloaded to `/tmp` and inspected without installation. Its post-install script creates the Horizon account, collects/compresses static assets, restarts memcached, and enables `openstack-dashboard.conf` in Apache. That config installs a global `/horizon` WSGI alias and grants access to the dashboard code/static directory. Do not enable this default path on the shared HTTP listener.
- The common package's default settings require an explicit review for allowed hosts, secure session/CSRF cookies, and the Keystone URL before deployment. The final login URL and working Keystone route are not yet verified.
- PowerShell reports WSL 2, WSL version 3.0.3.0, kernel 6.18.54.1-1, Windows version 10.0.26300.9711, no `.wslconfig`, and no explicit `netsh portproxy` entries. WSL's default networking behavior is documented as NAT; no outside-LAN reachability probe was performed. No firewall or monitoring service configuration was changed. Detailed firewall policy output is intentionally excluded from this public repository.

No Horizon package, Apache file, listener, or service was modified. Before installation, prepare a rollback-protected configuration that limits the dashboard to an approved TLS browser path and preserves existing API vhosts; verify the Horizon Keystone endpoint from a restored protected cloud session.

## Acceptance criteria

- [ ] A dedicated browser URL is verified from the intended Windows/WSL user context and is documented; it does not point to a raw API discovery document.
- [ ] TLS is enabled for the supported access path. Cookies are secure/HTTP-only, CSRF is enforced, session storage is suitable for the deployment, and secrets are injected from protected host configuration.
- [ ] Admin and tenant accounts authenticate through Keystone; no credentials are committed or duplicated in an application database.
- [ ] Existing Keystone, Placement, Glance, Nova, Neutron, Apache legacy routes, and retained VM health are checked before/after. Configuration backup, rollback and port ownership are recorded.
- [ ] Horizon panels are compared with scoped API results for the same users/projects.
- [ ] Operator runbook includes start, stop, health, TLS renewal, recovery and troubleshooting.

## Verification boundary

Package installation, Apache edits/reload, listeners, and live authentication change host state or contact protected services. First complete the read-only host review and present an exact change/rollback plan. The repository implementation goal does not authorize exposing a public listener.
