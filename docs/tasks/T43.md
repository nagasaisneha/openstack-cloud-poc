# T43 — Maintained Octavia service and customer load-balancer lifecycle

**Status:** Not implemented; provider templates/preflight are prepared, and live deployment depends on T46.

**Scope:** Matching Hibiscus Octavia API/driver-agent/OVN integration, service identity/catalog/policy/quota, Horizon panel, customer VIP/listener/pool/member/health-monitor lifecycle. OVN is selected for initial TCP load balancing; review full [design](../architecture/maintained-staging-design.md). No Amphora service is silently substituted and no Caracal Octavia package is installed.

**Prerequisites:** Maintained target, capacity, protected recovery, real provider availability, Neutron/OVN compatibility, project network/IPAM/SG configuration, two owned backend VMs and customer credentials. T42 is required for the external VIP route.

**Acceptance:** Authenticate customer, enumerate advertised provider/capabilities, create a load balancer with explicit provider/subnet, TCP listener and pool, two members and a TCP health monitor; require settled ACTIVE resources and project ownership. Verify positive own-project reads, other-project create/read/update/delete denial and provider quota rejection. Delete only owned monitor/member/pool/listener/LB resources in dependency order and verify absence. Actual traffic and failure recovery are required separately by T44; API ACTIVE cannot pass them.

**Implementation artifacts:** `deployment/kolla/globals.extended.example.yml` sets provider/agent and Horizon Octavia; `preflight.yml` requires reviewed network/health/provider and backend count. Exact service image/plugin digests, deployment, APIs and cleanup are unverified.

**Rollback:** Stop rollout and preserve configuration/reports; no shared OVN rows, tenant assets or source services are manually deleted. Repository template reversion is not database/provider rollback.
