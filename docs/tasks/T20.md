# T20 — Usage data source integration

**Status:** Locally verified for Nova compute allocation-hours; broader metering remains partial. A read-only Nova usage query returned three project-scoped allocation samples on 2026-10-26. Ceilometer/Gnocchi telemetry, network usage, and storage usage remain unavailable/unverified.

## Scope and traceability

- **Original requirements:** POC-018 — usage data collection; POC-020 — sample usage reporting.
- **Dependencies:** T07; T17 for a real test-VM source. The T17 fixture workflow is verified, while real Nova/Neutron execution remains blocked. Fixture records are allowed when no real workload is available.
- **Purpose:** Preserve usage provenance and project/resource scope, including measured Nova allocation-hours, without claiming a complete meter or billing-grade data.
- **Source boundary:** Nova `os-simple-tenant-usage` provides per-instance vCPU, RAM and local disk allocation-hours. It is not guest CPU utilization, network traffic, Cinder volume-hours, Swift bytes, or a complete Ceilometer/Gnocchi telemetry stream. No new meter service was installed.

## Files changed

- Added `openstack_cloud_poc/usage.py` with immutable raw usage samples, explicit `Decimal` quantities, UTC interval boundaries, units, source, and `observed`/`simulated` provenance.
- Added `FixtureUsageSource`, which returns only complete samples for an exact project and requested time window. It does not prorate partial intervals, convert units, or infer missing data.
- Added `FixtureUsageCollector`, which enforces the separate fixture `usage.read` / `usage.viewer` permission before reading project samples. Denied access does not call the source.
- Updated `openstack_cloud_poc/identity.py`, the provisioning-contract documentation, the POC requirements' implementation evidence, and the staging evidence crosswalk.
- Added focused tests in `tests/test_usage.py`.
- Added `openstack_cloud_poc/nova_usage.py`, which maps Nova's per-instance allocation-hours into `observed` samples, verifies project attribution, and rejects missing or invalid values.
- Added read-only `scripts/local-openstack/collect_nova_usage.py`. It uses the existing protected administrator credential and retained Task 11 project/server ownership, queries only the Nova usage endpoint, and writes a mode-0600 evidence report. No resource or service mutations are performed.
- The local OpenStack client provides `openstack usage show`; no Ceilometer/Gnocchi packages were found in the current package inventory. The live Nova API query is read-only and scoped to the retained Task 11 project's usage.

## Acceptance and limitations

- The local fixture source identifies `fixture:T20 illustrative usage; not measured`, returns samples only for the authorized project and requested complete intervals, and leaves empty results as “no matching fixture sample.”
- Usage units are preserved as supplied. No aggregation, unit conversion, interpolation, imputation, price calculation, invoice, or payment behavior is implemented.
- Nova measured compute allocation-hours are **verified locally** for the query window and project in the protected report. Values reflect Nova's API accounting and are not guest CPU utilization. No billing or invoice claim follows from this result.
- Ceilometer/Gnocchi metering, Cinder volume-hours, Swift object bytes, network usage, utilization telemetry and staging meter validation remain open. Fixture results remain explicitly simulated.
