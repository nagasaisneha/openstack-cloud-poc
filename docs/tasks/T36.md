# T36 — Swift object storage

**Status:** Blocked — no locally verified Swift/object-storage service

## Objective and scope

Expose tenant object containers and objects only if Swift or another approved OpenStack object service is deployed and verified.

**Dependencies:** T33 and verified object-service endpoint/storage.
**Mapped requirements:** Tenant object storage, status/errors, project isolation, usage/billing input, backup/restore.

## Current blocker

The 2026-10-24 read-only local inventory recorded no Swift executable, service unit, or listener on TCP 8080. The 2026-10-25 shell audit could not connect to the systemd bus or authenticate to the cloud API, so that historical observation has not been freshly revalidated. No object-service endpoint or storage topology is approved. The staging Kolla profile leaves Swift disabled until Gate 1 approves the ring and dedicated storage layout; its preflight requires a reviewed ring, at least three storage nodes, and replica count three. No external object store is assumed.

## Acceptance criteria

- [ ] The service catalog and policy show an enabled project-scoped object API with a supported storage backend.
- [ ] A disposable tenant creates a container, uploads an object, downloads and hash-checks it, and deletes only that test object/container.
- [ ] A second project cannot list/read/delete the first project's test data.
- [ ] Storage usage meters have verified units and project/resource attribution; request or egress charges are unavailable unless separately measured.
- [ ] If no service/backend exists, object storage is visibly unavailable; no external bucket or fixture is represented as Swift.

**Verification boundary:** No account, container, object, endpoint, or storage device operation was attempted. Real acceptance remains pending a supported service and approved task-owned test scope.
