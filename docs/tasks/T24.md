# T24 — Sample AI workload

**Status (T50, 2026-10-28): Local WSL GPU workload completed and verified; Nova tenant GPU access blocked by the actual device path.**

Fresh evidence: [GPU workload](../evidence/ai-gpu-workload-20261028.json), [runtime wheel hashes](../evidence/ai-runtime-20261028.json), [tenant device probe](../evidence/tenant-gpu-path-20261028.json). The seeded 64→256→4 MLP trained for 120 GPU steps on 4,096 synthetic examples and achieved 100% accuracy on 2,048 held-out examples. CPU/GPU output error was 1.91e-6 (limit 1e-4), peak CUDA reservation 88 MiB (limit 2 GiB), peak device utilization 29%, and total workload time 7.15 seconds (limit 120 seconds). Batch-2048 latency was 0.46 ms p50 and 0.99 ms p95. PyTorch 2.11.0+cu126/CUDA 12.6 ran on the RTX 2060; CPU fallback was disabled. CPU was used only as an explicit correctness reference. This is a small synthetic classifier acceptance, with no LLM performance claim.

WSL CUDA uses `/dev/dxg`. A pinned-SSH probe verified the existing tenant guest UUID and found zero NVIDIA PCI devices, no dxg/nvidia0 device and zero libvirt hostdev assignments. Tenant CUDA requires an approved bare-metal KVM compute host with assignable GPU PCI/IOMMU/reset support, Nova PCI scheduling and guest drivers; H100/MIG needs the actual supported hardware. The original POC-022 permits a proven host/container path, so local sample-AI acceptance passes. Tenant GPU offering remains blocked.
