# T37 — Real usage metering and attribution

**Status:** Scoped per-project collector and persistent usage history deployed; active-only/network meters and complete billing coverage remain open.

**2026-10-27:** A Horizon-owned one-minute timer collects three enrolled projects
with a separate reader/collector. Real Nova allocation samples and current
Cinder/Swift counters are retained in protected immutable snapshots and shown
in Horizon. Cumulative snapshots are not added together. Missing/stale meters
stay explicit. Actual CPU/network and complete active-state history remain
unavailable. See [T48](T48.md); one-off descriptions below retain prior history.

## Objective and scope

Collect real source-backed usage for supported billable resources. Evaluate release-compatible Ceilometer/Gnocchi as the telemetry path; use another source only with equivalent provenance, retention, completeness and project-scope evidence. CloudKitty may be evaluated for rating but is not required for data collection.

**Dependencies:** T33–T36 as applicable; chosen OpenStack release and meter source.
**Mapped requirements:** Distinguish allocated capacity/measured consumption/charges; real supported-resource usage; billing periods; controlled-workload verification.

## Current source evidence and remaining gaps

Task 20 records a protected, read-only Nova `os-simple-tenant-usage` query that returned three project-attributed allocation-hour samples on 2026-10-26. `NovaBillingUsageSource` now adapts that API to `BillingUsageSource`; it verifies a refreshed project-scoped Keystone session with the explicit `billing_collector` role before contacting Nova, records collection time and safe gap codes, and always marks the batch incomplete. Resulting statements are provisional with no total. The adapter and its billing path are covered by offline tests.

This is not an ongoing meter pipeline. The one-off T20 host collector used the root-only POC administrator credential, so that execution does not satisfy the required separate least-privilege collector identity. The billing adapter now enforces the intended project-scoped `billing_collector` role in code, but no live collector account/policy has been configured or verified. `NovaBillingUsageSource` follows bounded `limit`/`marker` pages and detects repeated pages or its page cap. It still reports `nova_pagination_unverified` because the deployed API microversion, configured `max_limit`, and page behavior have not been verified; a page shorter than the requested size alone cannot attest completeness. Nova also supplies no per-sample source timestamp or completeness/watermark contract in this integration. Its documented accounting uses the latest flavor for the duration the server existed while ignoring stop/pause events. This cannot prove an active-only charge interval or complete billing coverage. Statements preserve collection time and list known limitations as gap codes. Nova's `memory_mb` is MiB and `local_gb` is GiB; the adapter preserves those units explicitly. [Nova 2024.1 usage API](https://docs.openstack.org/api-ref/compute/#usage-reports-os-simple-tenant-usage).

No Ceilometer/Gnocchi, network, Cinder-volume or Swift-object meter is connected. The Nova source does not infer those values from fixtures or allocated capacity. The 2026-10-25 host audit measured 7.7 GiB total RAM; the separate Kolla staging candidate requires at least 8 GiB before any additional metering budget. Staging templates keep Ceilometer/Gnocchi disabled unless meter/resource review passes.

## Acceptance criteria

- [ ] Each metric documents source service/release, name, type, unit, resource/project IDs, source timestamp, ingestion timestamp, collection interval, retention and missing/late-data behavior.
- [ ] Compute charges use provider-confirmed active vCPU/RAM intervals. Nova's current simple-tenant-usage source is server-existence-based and ignores stop/pause events, so it cannot satisfy this criterion by itself. Actual CPU time/network bytes remain separate measured metrics where available.
- [ ] Volume/object metrics are enabled only after their service tasks pass.
- [ ] Duplicate, delayed, missing, out-of-order and corrected samples are reconciled without double charging.
- [ ] A controlled disposable test workload produces expected provider samples and project attribution; results reconcile independently with Nova/service state. The existing three-sample query used the retained project, not a controlled disposable workload.
- [ ] A missing or unsupported meter is shown as incomplete/unavailable, never as zero.
- [ ] A least-privilege collector identity separate from administrator and tenant credentials is deployed; meter access is denied to unauthorized projects. The one-off T20 script currently uses a protected administrator credential and does not pass this criterion.

## Capacity gate

No additional telemetry stack is installed on the laptop. Nova's existing usage API can be queried without installing Ceilometer/Gnocchi, but the separate Kolla staging template leaves those services disabled and the host remains below its documented 8-GiB staging baseline.
