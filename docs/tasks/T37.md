# T37 — Real usage metering and attribution

**Status:** Blocked — no verified local metering source; target deployment exceeds the laptop staging profile

## Objective and scope

Collect real source-backed usage for supported billable resources. Evaluate release-compatible Ceilometer/Gnocchi as the telemetry path; use another source only with equivalent provenance, retention, completeness and project-scope evidence. CloudKitty may be evaluated for rating but is not required for data collection.

**Dependencies:** T33–T36 as applicable; chosen OpenStack release and meter source.
**Mapped requirements:** Distinguish allocated capacity/measured consumption/charges; real supported-resource usage; billing periods; controlled-workload verification.

## Current blocker

No Ceilometer/Gnocchi source or project-attributed meter was found in the audited local package/service paths. The current shell cannot authenticate to Keystone or inspect the service manager. The existing local host has 7.7 GiB RAM in the 2026-10-25 audit, while the separate staging candidate requires at least 8 GiB for Kolla before any additional metering budget. Staging templates keep Ceilometer/Gnocchi disabled unless meter/resource review passes. No real usage is inferred from the T20 fixtures or T31's provider-shaped test data.

## Acceptance criteria

- [ ] Each metric documents source service/release, name, type, unit, resource/project IDs, source timestamp, ingestion timestamp, collection interval, retention and missing/late-data behavior.
- [ ] Compute allocated vCPU-hours and GiB-RAM-hours are derived from provider-confirmed active intervals. Actual CPU time/network bytes are separate measured metrics where available.
- [ ] Volume/object metrics are enabled only after their service tasks pass.
- [ ] Duplicate, delayed, missing, out-of-order and corrected samples are reconciled without double charging.
- [ ] A controlled disposable test workload produces expected provider meter samples and project attribution; results reconcile independently with Nova/service state.
- [ ] A missing or unsupported meter is shown as incomplete/unavailable, never as zero.
- [ ] Collector identity is least-privilege and separate from admin and tenant credentials; meter access is denied to unauthorized projects.

## Capacity gate

No telemetry stack is installed on the laptop until memory/service budget is measured against the core services. Current shell evidence shows 7.7 GiB total RAM and 3.2 GiB available, while the separate Kolla staging template disables Ceilometer/Gnocchi by default.
